# Capsid v0.3.2-beta.1

Experimental `0.3.2-beta` release (runtime version `0.3.2`, public **C ABI v8**,
**FetchRPC v4-only**), published as the default GitHub `Latest` release
(`v0.3.2-beta.1`). The maintained `0.2.x` stable line (`v0.2.2`) remains
available by explicit tag.

## Highlights

- **Config v2 (`capsid/host-v2` and `capsid/app-v2`) & Unified Local CLI**:
  Retires `host-v1`/`app-v1` and legacy `--mode single-worker` / `static-pool`
  flags in favor of one managed-isomorphic `capsid-host --app-dir <dir>` local
  Host across Linux, macOS, and Windows.
- **Elastic OS Process Pools (Linux Managed Mode)**: Scale-to-zero (`minReady: 0`),
  bounded cold-request queueing, two-stage tenant-fair eviction (`85% / 75%`
  hysteresis), immediate capacity slot handoff with asynchronous worker OS exit
  reclamation, live-traffic rolling drain up to `drain_deadline`, and shared
  delegated tenant `cgroup v2` `memory.max` accounting.
- **Public C ABI v8 & FetchRPC v4-only**: Removes legacy ABI v7 and FetchRPC v3
  paths, adds Build Info v2 and Capability Policy v2, and keeps `quickjs-turbo`
  `v0.15.1-turbo.8` zero-JIT native register-frame interpreters across Linux
  (`x86_64`/`arm64`), macOS Intel (`x86_64`), and Windows (`x86_64`).
- **Verified Five-Platform Native Archives**: Fully static musl Linux
  (`x86_64`/`arm64`), native thin macOS (`arm64`/`x86_64`), and static-CRT
  MSVC Windows (`x86_64`).

## Install

Install `v0.3.2-beta.1` on Linux or macOS:

```sh
curl -fsSL https://github.com/rowanellis-113/capsid/releases/download/v0.3.2-beta.1/install.sh \
  | CAPSID_REPO=rowanellis-113/capsid bash -s -- v0.3.2-beta.1
```

On Windows PowerShell (`x86_64`), verify the ZIP against its `.sha256` sidecar
and extract it into a clean directory. Do not mix the Host, worker, compiler, or
SDK across builds; rebuild embedders against ABI v8 and recompile trusted
bytecode for the matching compatibility ID. See the
[installation guide](https://github.com/rowanellis-113/capsid/blob/dev/v0.3.2/docs/guides/install-packages.md)
for OS/architecture selection and verification.

Linux strict sandboxing requires the documented kernel and delegation
prerequisites. Native macOS and Windows builds are for trusted development and
integration. The pinned compatibility profile retains five raw WPT file
failures; green CI is not full standards conformance. The accepted `dev/v0.3.2`
local WSL2 benchmark session (`24671d9`) measures a local Release/LTO rebuild
and does not measure the distributed release archives directly.
