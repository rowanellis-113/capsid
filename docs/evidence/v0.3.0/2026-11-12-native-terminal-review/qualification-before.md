## Density Preheating Protocol and Actual Coverage

Production keeps least-loaded scheduling, the lowest slot as the tie-breaker, and one App. The QPS test keeps concurrency at 64. Base density concurrency is 64 and the warm-up ceiling is `max(64, 64 × pool size)`. A single sender writes the whole wave of real GET requests before reading and checking each HTTP status and response body. Connection preparation uses at most 64 threads.

The cold request limit is `max(64, pool size × target count × 8)` and the warm limit is `max(64, pool size × target count × 32)`. The coverage deadline remains 300 seconds. The warm multiplier increased from 8 to 32 under the approved density warm-up protocol. The SPEC, producer metadata and independent evidence validator record the change. Archives using the older protocol do not qualify under the new one. A last wave finishing at or after the deadline must fail even if it meets the target count.
